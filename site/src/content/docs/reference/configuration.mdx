## Configure the `icon` integration

Pass options to `icon({ … })` in **`astro.config.mjs`**:

```diff lang="js" title="astro.config.mjs"
import { defineConfig } from 'astro/config';
+ import icon from 'astro-iconset';

export default defineConfig({
	integrations: [
+		icon({ /* options */ })
	]
});
```

All options are optional. Defaults are noted per option below.

---

### `include`

**Type:** `Record<string, string[]>`  
**Default:** `{}` (all installed `@iconify-json/*` icons are included)

Filter which Iconify icons to include in the final server bundle. Only relevant for `output: 'server'` or `output: 'hybrid'` — static builds resolve everything at build time.

```js {7-12}
import { defineConfig } from "astro/config";
import icon from "astro-iconset";

export default defineConfig({
  integrations: [
    icon({
      include: {
        // Include only these `mdi` icons in the bundle
        mdi: ["account", "account-plus", "account-minus"],
        // Or include an entire set (can be large):
        // mdi: ['*'],
      },
    }),
  ],
});
```

<Aside type="caution">
  Without `include`, **all icons from every installed `@iconify-json/*`
  package** are included in the server bundle. For large sets this can add
  megabytes to your deployed function. See [Deployment & SSR
  bundles](/guides/deployment/) for guidance.
</Aside>

---

### `iconDir`

**Type:** `string | string[]`  
**Default:** `"src/icons"`

The directory (or directories) from which local SVG files are loaded. Files are referenced by their path relative to this directory, without the `.svg` extension.

**Single directory:**

```js {7}
import { defineConfig } from "astro/config";
import icon from "astro-iconset";

export default defineConfig({
  integrations: [
    icon({
      iconDir: "src/assets/icons",
    }),
  ],
});
```

**Multiple directories** (merged into the same `local` set — duplicate file names across folders cause a build error):

```js
icon({
  iconDir: ["src/icons", "src/assets/icons"],
});
```

<Aside type="note">
  Do not set both `iconDir` and `iconDirs.local` at the same time. Use one or
  the other.
</Aside>

---

### `iconDirs`

**Type:** `Record<string, string>`  
**Default:** `{}` (no named directories)

Map prefix names to directories. Each icon in a named directory is referenced as `prefix:name` instead of just `name`. Useful for avoiding name collisions when mixing icon sets from multiple folders.

```js
icon({
  iconDirs: {
    brand: "src/brand-icons",
    ui: "src/ui-icons",
  },
});
```

Reference icons with their prefix:

```astro
<Icon name="brand:logo" />
<Icon name="ui:menu" />
```

To replace the default `local` (unprefixed) directory with a named one, set `iconDirs.local`:

```js
icon({
  iconDirs: {
    local: "src/my-icons", // replaces the default src/icons
    brand: "src/brand-icons",
  },
});
```

<Aside type="note">
  Do not set both `iconDir` and `iconDirs.local` — they control the same thing.
</Aside>

### `svgoOptions`

**Type:** [`Config`](https://github.com/svg/svgo/blob/main/lib/svgo.d.ts) (SVGO config object)  
**Default:** SVGO runs with `preset-default` — removes metadata, comments, and redundant attributes

Override the SVGO configuration used to optimize local `.svg` files at build time. See the [SVGO configuration docs](https://github.com/svg/svgo#configuration) for all available plugins and options.

```js {7-24}
import { defineConfig } from "astro/config";
import icon from "astro-iconset";

export default defineConfig({
  integrations: [
    icon({
      svgoOptions: {
        multipass: true,
        plugins: [
          {
            name: "preset-default",
            params: {
              overrides: {
                // Customize a default plugin option
                inlineStyles: {
                  onlyMatchedOnce: false,
                },
                // Or disable a default plugin
                removeDoctype: false,
              },
            },
          },
          // Convert hard-coded fill/stroke to currentColor so CSS color works
          {
            name: "convertColors",
            params: { currentColor: true },
          },
        ],
      },
    }),
  ],
});
```

<Aside type="tip">
  If icons appear invisible or ignore CSS `color`, the source SVG may use a
  hard-coded fill. Add the `convertColors` plugin (shown above) to replace it
  with `currentColor`. See
  [Troubleshooting](/guides/troubleshooting/#icon-color-does-not-change-with-color-or-tailwind-text)
  for more.
</Aside>

### `dataAttr`

<Badge text="New" variant="tip" />

**Type:** `string | false`  
**Default:** `"data-icon"`

The data attribute added to each rendered icon. It identifies the icon and acts as a CSS hook (`[data-icon]`, `[data-icon="mdi:account"]`). Pass a custom name to rename it, or `false` to omit it entirely.

```js {7}
import { defineConfig } from "astro/config";
import icon from "astro-iconset";

export default defineConfig({
  integrations: [
    icon({
      dataAttr: "data-astro-icon", // rename — or set `false` to remove it
    }),
  ],
});
```

The default `"data-icon"` is backward compatible — leave it unset unless you need a different attribute name or want to drop it. See [CSS &amp; styling](/guides/styling/) for how the attribute is used in selectors.
